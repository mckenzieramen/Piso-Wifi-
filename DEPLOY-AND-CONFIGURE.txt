PISO WIFI — CASHIER LOADING + PERMANENT DELETE FIX
Date: 2026-10-11

This package addresses two separate issues:
A) Cashier portal can remain at sign-in after Firebase auth if the users/{uid} profile lookup hangs. It now has a 12-second timeout and displays an actionable error instead of hanging silently.
B) Admin Cashier Management's permanent-delete button calls /api/admin/delete-cashier. The function is included at functions/api/admin/delete-cashier.js and must be deployed to Cloudflare Pages.

Deploy these files into matching paths, preserving the rest of the website:
- cashier.html
- js/cashier.js
- admin/dashboard.html
- js/dashboard.js
- functions/api/admin/delete-cashier.js

IMPORTANT: This code cannot set Cloudflare secrets itself. The screenshot error "Permanent deletion endpoint is not configured yet" means these secrets are missing:
1. FIREBASE_PROJECT_ID = piso-wifi-f2b5c
2. FIREBASE_API_KEY = the existing Web API key from js/firebase-config.js
3. FIREBASE_SERVICE_ACCOUNT_JSON = full service account JSON for this Firebase project, saved as a Cloudflare SECRET (never in public code or chat).

The service account needs the required Identity Toolkit Admin permissions to delete Firebase Authentication users and Firestore permissions to read/delete users/{uid}. After adding secrets, redeploy Pages. Test with a disposable cashier account first.

The delete endpoint removes the Firebase Authentication login and users/{uid} profile; existing sales/history are intentionally retained. If secrets are not configured, the endpoint refuses to delete and the account remains in the list. This package has not been deployed to the live site.
