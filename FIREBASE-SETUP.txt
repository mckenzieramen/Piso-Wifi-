BIG GUY'S CARWASH — FIREBASE CENTRAL SYNC

This build keeps the existing face-recognition DTR, admin dashboard, employee management, sales, payroll, reports, and local cache. Firebase is used as the central source for cross-device synchronization.

FIREBASE WEB APP CONFIG
The Firebase web configuration from the registered Big Guys Carwash web app is already included in firebase-config.js.

ONE CONSOLE STEP REQUIRED
1. Firebase Console > Authentication > Sign-in method.
2. Keep Email/Password enabled.
3. Also enable Anonymous.
4. Save.

FIRESTORE RULES
Replace the current Firestore rules with the following and Publish:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function signedIn() {
      return request.auth != null;
    }

    function admin() {
      return signedIn()
        && request.auth.token.firebase.sign_in_provider == 'password'
        && request.auth.token.email == 'bigguy@admin.com';
    }

    match /bigguys/{docId} {
      // Employee DTR needs to read the employee/face data and attendance state.
      allow read: if signedIn() && (docId == 'public' || docId == 'attendance') || admin();

      // Only the authenticated administrator can change employee/face/business data.
      // Anonymous DTR sessions may write attendance only.
      allow write: if admin()
        || (signedIn()
            && request.auth.token.firebase.sign_in_provider == 'anonymous'
            && docId == 'attendance');
    }
  }
}

DATA DOCUMENTS
- bigguys/public      = employees + enrolled face descriptors
- bigguys/attendance  = DTR records + latest captured face preview
- bigguys/business    = sales + daily reports

The browser keeps localStorage as an offline cache, but successful Firebase synchronization is shared across devices.

SECURITY NOTE
Face descriptors are biometric-related data. Use only with appropriate employee consent, access control, and retention practices. The DTR client needs read access to the public document so it can recognize enrolled employees; for a stricter production architecture, move recognition behind a secured backend/service.

- Firebase Authentication user: bigguy@admin.com
- Firestore document: admins/{Firebase UID}
