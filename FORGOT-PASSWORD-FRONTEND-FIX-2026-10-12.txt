PISO WIFI — FORGOT PASSWORD FRONTEND FIX
Date: 2026-10-12

WHAT THIS PATCH DOES
- Updates the cache-busting version on the canonical login pages so browsers load the current customer-login JavaScript instead of stale cached code.
- Makes Client ID validation explicitly normalize input and accept the existing CID-0005 style (CID- followed by at least three digits).
- Applies the same validation fix to the duplicated customer-login script copies included in this repository.
- Does not delete, overwrite, migrate, or recreate customer records.
- Does not change Firebase configuration or the Apps Script endpoint.

IMPORTANT LIMITATION
This fixes the front-end validation/cache issue only. If the OTP request reaches the server and then fails, the Apps Script / Firestore lookup and permissions need a separate backend fix. The Google Sheet screenshot being empty does not prove Firestore is empty.

DEPLOY STEPS (Cloudflare Pages)
1. Keep a copy of your current deployed project/ZIP as a backup.
2. Extract this ZIP on your computer.
3. Open the extracted folder and enter the inner folder named "Piso-Wifi--main".
4. Upload/deploy the CONTENTS of that inner folder as the Cloudflare Pages project. Do not upload the outer ZIP itself as a website file.
5. Wait for the deployment to finish.
6. Open https://piso-wifi.pages.dev/client-login.html in a private/incognito window, click Forgot Password, and enter the exact existing Client ID (example: CID-0005) and its registered Gmail.
7. Click Get OTP once.
8. If the message now changes to "Checking your account..." / "Sending OTP..." and then reports a server-side error, the front-end validation is passed. Do not keep retrying OTP. Send the exact server error so the Apps Script/Firestore backend can be repaired next.

DO NOT
- Do not clear or delete Firestore collections.
- Do not re-register existing customers to work around this.
- Do not replace the Apps Script deployment with an older Code.gs.
- Do not share passwords, OTPs, or private service-account keys.
