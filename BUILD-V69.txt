PISO WIFI BUILD V69 - CUSTOMER FIRST LOGIN SESSION FIX

Root cause confirmed from v68 runtime error:
- Customer dashboard reached first-login password setup, but sessionStorage did not contain the temporary password.
- v68 therefore raised auth/missing-temporary-password before it could update Firebase Auth.

Fix:
- Successful Customer logins now store the just-used credential in sessionStorage whenever the authenticated account is a client.
- This no longer depends on forcePasswordChange being present on users/{uid}; that flag may live on the unit record.
- The credential is still removed after successful password change.
- Bumped Customer login cache-buster to v69.

Preserved:
- Admin auth and routing
- Firebase config
- Firestore rules
- Apps Script / OTP flow
- Existing dashboard and UI
