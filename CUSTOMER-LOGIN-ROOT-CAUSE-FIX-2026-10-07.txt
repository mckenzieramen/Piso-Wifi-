PISO WIFI — CUSTOMER LOGIN ROOT-CAUSE FIX — 2026-10-07

Changed ONLY the customer authentication handoff.

Root cause addressed:
The customer login treated any failure while reading users/{uid} as a failed Firebase login.
That meant a valid Firebase Auth login could still show the generic "Login failed" message if the
customer profile document was missing/unavailable, even when the linked units record was present.

Fix:
1. Customer login still authenticates with Registered Gmail + temporary Client ID password.
2. After Firebase Auth succeeds, it first reads users/{uid}.
3. If that profile is missing/unavailable, it safely falls back to units.authUserId == Firebase UID.
4. For legacy records, it can also fall back to units.email == registered Gmail.
5. The existing role/active checks and customer routing remain intact.
6. The login page now shows the actual Firebase error code/message instead of a misleading generic popup message.
7. No Admin auth flow, Firestore data, Apps Script, or Firebase rules were changed.
