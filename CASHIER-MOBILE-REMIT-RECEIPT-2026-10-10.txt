PISO WIFI CASHIER MOBILE + REMIT + RECEIPT HISTORY UPDATE
Build: 2026-10-10-2330

Included:
- Responsive mobile navigation and smaller-screen cashier layout.
- Removed Dashboard and My Collection from cashier navigation. Enter Sale contains only the sale form and earnings summaries; Sales History is no longer embedded there.
- Receipt page is receipt history only. Amounts are blurred by default and can be revealed; each paid receipt has View Receipt and Resend Email actions.
- Receipt email uses a designed HTML template and targets the customerEmail saved on that sale record. It no longer opens a mailto draft.
- Added Cloudflare Pages endpoint functions/api/send-receipt.js.
- Remit totals are blurred until cashier re-enters their password. Leaving the Remit tab or hiding the browser tab locks it again. Remit Now asks for exact cash-in-hand and recipient name, calculates Short/Over, then asks Are you sure before submission. History shows date/time, recipient, expected, actual, and Short/Over.
- Preserved the existing Customer ID check and sale confirmation popup.

IMPORTANT EMAIL SETUP:
Automatic HTML email will NOT send until these server-side Cloudflare Pages environment variables are configured:
- FIREBASE_WEB_API_KEY = Firebase Web API key for the existing project
- RESEND_API_KEY = Resend API key
- RECEIPT_FROM_EMAIL = verified sender address/domain in Resend
The email provider account/domain must be verified. Without these settings, the app reports that email service is not configured rather than claiming an email was sent.

IMPORTANT REMITTANCE RULES:
The remittance expected total is calculated as gross sales minus customer earnings for unremitted transactions. Firestore rules must permit cashiers to create remittances and mark their own transactions with remittanceId. Rules were not changed in this package. Test with a cashier account before production use.

Validation performed: JavaScript syntax checks and ZIP integrity check. Not deployed and not live-tested against Firebase/Cloudflare.
